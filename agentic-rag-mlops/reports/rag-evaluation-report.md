## 2. System under evaluation

The system comes from `plan.md` and `research.md`. The settings come from the `config` block of `latest.json`.

- **Pipeline:** a sequential CrewAI crew with two agents. (1) A **Knowledge Retriever** agent calls the
  `search_knowledge_base` tool. The tool embeds the question, queries ChromaDB (cosine), and returns the top-k
  chunks as delimited `<<<EVIDENCE id=...>>>` blocks with their scores. (2) An **Answer/Verifier** agent writes a
  structured `AnswerDraft` with a status, an answer, citations, and the missing evidence.
- **Retrieval settings:** `top_k = 6`, `MIN_RELEVANCE = 0.30` (score = 1 − cosine distance), chunks of 800
  characters with 120 overlap. These match the defaults in `app/config.py`, so the run used default settings.
- **Guardrail (R6):** deterministic and implemented in code, not a judge. Every citation must be a chunk that was
  actually retrieved. An answered or partial draft needs at least one citation. A not-found draft must use the
  exact safe message. If no chunk reaches `MIN_RELEVANCE`, the guardrail returns the safe answer without asking the
  model. The guardrail allows up to 2 retries before falling back to the safe answer.
- **Injection handling (R7):** a regex screen flags chunks with planted instructions. Flagged chunks are kept as
  quoted evidence and recorded in the trace.
- **Tracing (R8):** each question produces one Langfuse trace (`rag-question`). The trace holds the
  OpenInference CrewAI and OpenAI spans, plus the project's own `retriever` and `guardrail` observations. Session
  and request ids are random UUIDs.
- **Knowledge base:** 5 sample files (`.md`, `.txt`, `.pdf`) split into 22 chunks.

## 9. Limitations

- **Tiny sample:** 8 questions (7 with expected sources, 1 each for unanswerable, partial, and injection). One
  question changes a rate by 0.125–0.143, and no confidence intervals are possible.
- **Synthetic, self-written knowledge:** 5 short documents (22 chunks) written for this project.
- **Keyword proxy for correctness:** answer-point coverage checks keywords, not meaning. A correct paraphrase can
  fail it, and a wrong answer that contains the keyword can pass it.
- **Document-level relevance labels:** precision@k and nDCG count any chunk from a non-expected document as
  irrelevant, even when it contains the answer (the glossary).
- **No judge or human ratings:** faithfulness, answer relevance, and rubric scores are missing.
- **Single run per configuration:** LLM output is non-deterministic, and only one pair of repeated runs exists.
- **Regex injection screen:** it catches only known phrasings. Paraphrased, encoded, or non-English injections
  would pass, and the detection rate rests on n = 1.
- **Settings tuned on the test set:** top_k and `MIN_RELEVANCE` were chosen on the same questions they are
  evaluated on.

## 10. Data-quality concerns

- **Optimistic bias:** the questions, expected answers, and documents were written by the same person, so the
  questions use the documents' own vocabulary.
- **Glossary as a distractor:** `mlops-glossary.md` repeats facts from the project notes. This is the direct cause
  of the q4 and q8 citation misses, and it lowers precision@k under document-level labels.
- **Synthetic injection test:** the injection document is artificial and uses an obvious phrasing the regex was
  written to catch.
- **Few chunks:** with 22 chunks and k = 6, each query retrieves 27% of the corpus. Chunk coverage of 0.955 shows
  that retrieval is barely selective at this scale, so the retrieval metrics will not transfer to a larger corpus.
- **Thin abstention margin:** the unanswerable question's best score (0.289) is only 0.011 below the threshold. A
  slightly closer distractor would make the system answer instead of abstaining.

## 12. Recommended next experiments

1. **LLM judge for faithfulness and answer relevance**, calibrated against ~30 human labels with raw agreement
   and Cohen's κ. Check it for leniency, verbosity, and self-preference bias before trusting it (HW3 slide 11).
   This fills the two largest Unavailable rows.
2. **Fix and re-measure the citation choice on q4/q8.** Add a prompt rule to prefer the most specific source over
   the glossary, or label glossary chunks as acceptable evidence. Then decide how SC-004 should be worded.
3. **Grow the dataset to ≥ 30 questions.** Include hard negatives near the 0.30 threshold, more unanswerable and
   partial cases, and paraphrased injections, written by someone other than the document author. Use a held-out
   split so top_k is not tuned on the test set.
4. **Sweep `MIN_RELEVANCE` and top_k** using the score distributions. The current threshold separates answerable
   from unanswerable questions by only 0.011. Report abstention precision and recall over the sweep.
5. **Repeated runs (≥ 5 per configuration)** to estimate variance, then compare configurations with intervals
   instead of single values.
6. **Chunk-level relevance labels** so that precision@k and nDCG do not penalise correct glossary passages.
7. **Resource monitoring** (`psutil` CPU, memory, and disk) during evaluation, and a PII scan of the exported
   traces.
8. **CI regression gate** on hit@k, status accuracy, and citation correctness, using the offline suite plus a
   nightly live evaluation.

## Appendix: metric definitions

From `specs/001-agentic-rag/contracts/evaluation-dataset.md`, mapped to the Homework 3 slides.

| Metric | Definition | HW3 slide |
|---|---|---|
| Hit@k | 1 if any top-k chunk comes from an expected source, else 0 | 9 (retrieval quality) |
| Recall@k | Expected documents found in the top k ÷ expected documents | 9 |
| Precision@k | Chunks from expected sources in the top k ÷ chunks returned | 9 |
| MRR | 1 ÷ rank of the first relevant chunk (0 if none) | 9 |
| nDCG@k | DCG with binary chunk relevance ÷ ideal DCG | 9 |
| Citation correctness | Cited ids that were retrieved **and** come from an expected source ÷ cited ids | 9 (faithfulness proxy) |
| Citation completeness | Expected sources cited ÷ expected sources | 9 |
| Answer-point coverage | Expected points whose keywords appear in the answer ÷ expected points | 9 (answer relevance proxy) |
| Status accuracy | Items whose status equals `expected_status` ÷ items | 9 (hallucination and abstention) |
| Context utilisation (Derived) | Mean of cited chunks ÷ evidence chunks over answered and partial items | 9 |
| Faithfulness, answer relevance | Judge or human rating; not collected | 10, 11 |
| Latency median, p95, max; tokens; cost | From the evaluation timer and the Langfuse export | 9 (cost and latency), 12 (tail latency, SLO) |
| Trace completeness, error rate | From the Langfuse export | 14 (monitoring) |
| Injection detection, secret scan | Regex flags; string scan | 9 (safety) |
